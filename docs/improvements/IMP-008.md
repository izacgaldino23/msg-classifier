# Melhoria do CLI

Hoje o CLI (Command Line Interface) do bot é muito limitado e não possui muitas funcionalidades. Isso dificulta a utilização do bot, pois o usuário precisa digitar comandos complexos para realizar ações simples.

Uma forma de melhorar isso é criar um CLI mais amigável e intuitivo, com comandos mais simples e fáceis de lembrar. Além disso, podemos adicionar funcionalidades que facilitem a utilização do bot, como a possibilidade de listar os comandos disponíveis, exibir mensagens de ajuda e fornecer feedback ao usuário sobre as ações realizadas.

Pensei em usar uma biblioteca, https://go-tui.dev/. Elá é bem conhecida é ja em Go, então não precisamos nos preocupar com dependências externas. Ela também é bem documentada e possui exemplos de uso, o que facilita a implementação.

Antes de implementar quero que seja feito junto do plano um esboço de como o CLI vai ficar, com os comandos que ele vai ter e como eles vão funcionar. Isso vai ajudar a ter uma visão geral do que queremos implementar.

Pensei que para o esboço poderia usar algo simple como Ferramentas Visuais de Texto Puro (ASCII / Unicode Art), posso usar para visualizar dentro de um bloco de código em um arquivo markdown, ou posso usar uma ferramenta online como https://asciiflow.com/ para criar o esboço e depois exportar para um arquivo de imagem.

Assim acho que ficaria mais fácil confirmar o que eu quero antes de executar a implementação.

## Resultado (implementado em 2026-10-09)

A análise mudou duas coisas do que está escrito acima: **a `go-tui.dev` não foi usada** e o CLI não virou uma TUI de tela cheia.

- A go-tui é codegen (arquivos `.gsx` compilados para `.go`) e roda em alternate screen: custo de build/CI igual ao do `swag` e uma reescrita dos testes do REPL, para um problema que não era de tela. O que faltava era comandos, ajuda, listagem e feedback — e isso não precisa de dependência nova.
- O CLI ganhou comandos com aliases, filtros em PT-BR, tabelas com borda, cartões para os registros, cores ANSI (desligadas quando a saída não é um terminal), eco da mensagem, o indicador `classificando…` e uma linha de erro que não derruba a sessão.
- Zero dependência nova; `internal/cli` continua sem importar `views`/`api`. A descrição técnica está em `ARCHITECTURE.md` §15 e §15b.

```
msg> /ajuda

  ┌ Comandos ──────────────────────────────────────┐

  │ /notas [filtro] [termo]      lista notas       │
  │ /financas [filtro] [termo]   lista finanças    │
  │ /limpar                      limpa a tela      │
  │ /sair                        encerra           │
  └────────────────────────────────────────────────┘
    Qualquer outra linha é enviada como mensagem.
    Use /ajuda <comando> ou <comando> --ajuda para ver os filtros e exemplos.
```

Um duplicado abre o loop de confirmação de sempre (`u` / `n` / `c`), e um comando digitado nessa hora cancela o pendente e roda — os dois laços não engolem a linha um do outro. Um comando desconhecido ou um filtro inválido imprimem uma linha (`✗ Comando desconhecido: /xyz. Use /ajuda.`) e voltam ao prompt.

## Busca e ajuda por comando (2026-10-09)

A primeira versão só listava: para achar um contato era preciso abrir o `/data` no navegador. As três listagens agora **aceitam um termo de busca**, e o `/ajuda` ficou curto, com o detalhe por comando.

```
msg> /contatos iza
  ┌ 1 contato(s) ───────────────────────────┐
  │ ID   nome           telefone      email │
  ├─────────────────────────────────────────┤
  │  6   Izac Galdino   88996019489   —     │
  └─────────────────────────────────────────┘

msg> /contatos telefone 8899        ← filtra (tem telefone) e busca
msg> /notas lembrete pagar          ← lembretes que contenham "pagar"
msg> /financas compra mercado       ← compras do mercado
```

Regra única nas três: a **primeira palavra é filtro só quando nomeia um**; o resto é o termo. Por isso `/notas pagar` busca e `/notas lembrete pagar` filtra e busca. A busca usa a mesma infraestrutura do `/data` e da API — `name_norm` (sem acento, sem case) + telefone + e-mail nos contatos, `LIKE` no conteúdo das notas, e conteúdo + estabelecimento nas transações; o `?search=` foi adicionado também ao `/contacts` e `/notes` da API, de graça.

O detalhe de cada comando sai com `comando --ajuda` (ou `-h`, ou `/ajuda comando`):

```
msg> /contatos --ajuda

  ┌ /contatos ────────────────────────────────────────────────┐
  │ Lista os contatos, mais novos primeiro.                   │
  │                                                           │
  │ filtros:                                                  │
  │   todos     todos os contatos                             │
  │   telefone  só quem tem telefone                          │
  │   email     só quem tem e-mail                            │
  │   nome      só quem tem apenas o nome                     │
  │                                                           │
  │ sem filtro, a palavra seguinte é o termo de busca:        │
  │   /contatos silva        busca em nome, telefone e e-mail │
  │   /contatos telefone 11  filtra e busca                   │
  └───────────────────────────────────────────────────────────┘
```

O texto do detalhe vem do locale (`cli.help.<comando>.detail`), e um teste confere que toda palavra de filtro do comando aparece no seu detalhe — para o texto não envelhecer sozinho.
