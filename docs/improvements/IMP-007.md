# Centralizar mensagens de texto

Hoje não temos uma forma de centralizar as mensagens de texto que o bot envia para o usuário. Isso pode gerar inconsistências e dificultar a manutenção do código, pois cada mensagem está espalhada em diferentes partes do código.

Uma forma de melhorar isso é criar um arquivo de mensagens centralizado, onde todas as mensagens de texto que o bot envia para o usuário estarão armazenadas. Isso facilita a manutenção do código, pois todas as mensagens estarão em um único lugar, e também ajuda a evitar inconsistências, pois todas as mensagens serão padronizadas.

Assim ja teremos um terreno preparado para internacionalização, caso seja necessário no futuro. Por agora, podemos manter as mensagens em português, mas futuramente podemos adicionar suporte a outros idiomas.

O objetivo principal dessa melhoria é facilitar a manutenção do código e garantir que todas as mensagens de texto que o bot envia para o usuário estejam centralizadas em um único lugar, evitando inconsistências e facilitando a padronização das mensagens.

## Implementação

O texto foi para fora do Go. Nasceu o `internal/messages`, um pacote leaf (só stdlib + `models`) em que **nenhum arquivo `.go` tem literal em português**: a redação vive em `locales/pt-BR.json`, embutido com `go:embed` e lido com `encoding/json` — o mesmo padrão dos templates do `pkg/jev`. Um segundo idioma é só outro arquivo com as mesmas chaves.

Cada mensagem é uma **função tipada** (`messages.ContactSaved(id)`, `messages.NoteSaved(kind, id)`, `messages.BadRequest()`), nunca uma chave crua no call site: é isso que mantém a aridade, o `· ID %d` e a caixa iguais entre o CLI e a API. `T(key)` devolve a própria chave quando a entrada falta, e um arquivo quebrado carrega como mapa vazio — o caminho de requisição nunca entra em pânico nem renderiza um card vazio. Layout continua com a superfície (indentação, `": "`, HTML); a locale carrega só as palavras.

O que entrou: os três presenters (`cli/render.go`, `api/presenter.go`, o `labelMap` do `views`), os literais de erro dos controllers, os três fragmentos `Missing` do finance e o texto do REPL (banner, `Cancelado.`, opções do `u`/`n`/`c`, linha de erro, rótulos de campo). O que ficou de fora: a cópia dentro dos templates (`resultado`, `error`, tabelas) e os ~45 diagnósticos internos em inglês — que continuam vazando por `err.Error()` como antes.

Ganhos colaterais: o `noteKind` triplicado (views + api + cli) virou um switch só, e o bug de gênero do CLI — "lista de tarefas **salvo**" — morreu com ele; a API agora devolve PT-BR para sentinela conhecida (`{"error":"Registro não encontrado."}`) sem mudar status nem contrato; e o mapa de badges passou a ser lido do mesmo lugar que o resto do texto. A deriva entre web e CLI/API permanece nesta rodada, porque a cópia do HTML ficou de fora de propósito.
