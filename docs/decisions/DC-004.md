# Testes de validação das requisições do jev

Preciso ter uma forma de gerar muitos tipos de mensagens para validação e proprio melhoramento da nossa forma de enviar para o jev. Como o jev só pode rodar manualmente por mim por conta da chave, vamos criar uma página aqui que deve ser um endpoint, nela vamos ter muitos exemplos de mensagens que vamos gerar e guardar localmente no projeto. Essa tela vai me permitir escolher qual fluxo do jev temos no sistema, que por enquanto é o de classificação da mensagem e o de verificar qual parte do texto bate com o nome do usuário.

Quando eu escolher qual fluxo, deve aparecer em tabela a lista de prompts de exemplos para cada caso. Nessa tabela deve haver um checkbox em cada linha, default desmarcados, eu poderei selecionar quantos eu quiser, ou marcar/desmarcar todos de uma vez. Quando clicar no botão de avaliar, a api vai disparar sincronamente requisições ao jev para cada uma assim, teremos um resultado do jev para poder melhorar o desempenho dos nossos prompts. 

Cada prompt (mensagem), deverá ter salvo com si o resultado desejado, falando do resultado em si, não as porcentagens. Assim, para cada resultado teremos uma avaliação visual para o usuário ter um feedback real das que estão funcionando ou não.

O resultado além de visual deve ser possível para que eu salve em um arquivo csv, contendo o id da mensagem, resultado esperado, resultado obtido e a data de execução.

## Onde as mensagems devem ficar salvas?

Acredito que podemos ter uma tabela no banco para deixa-las salvas, quero poder adicionar também pelo ui. Inicialmente vou querer ter alguns já salvos, podemos criar um arquivo sql na pasta scripts/sql assim será fácil de zerar o banco e readicionar rapidamente.

Os resultados não devem ser salvos por enquanto, somente com a opção do próprio usuário, após rodar as requisições, exportar como csv. Acho que podemos ao inves de mandar o resultado par ao usuário baixar, salvar como csv em uma pasta aqui do projeto, com o nome da requisição, data e hora.

## Implementação (2026-09-23)

Vamos construir uma página `/prompts` (Validação Jev) que lista exemplos de mensagens salvos no banco, com um seletor de fluxo (classificação ou extração de nome) e uma tabela com checkboxes para escolher quais avaliar. Ao clicar em "Avaliar", a API roda os prompts selecionados contra os mesmos serviços de produção (ClassificationService e ContactExtractor), comparando o resultado obtido com o esperado (formato `categoria:acao` para classificação, nome normalizado para extração). O resultado aparece em uma tabela visual com ✓/✗ e o trace de segmentos para o fluxo de nome; "Exportar CSV" re-executa a avaliação e salva em `exports/<fluxo>-<data-hora>.csv`. A stack segue o padrão MVC do projeto: model `JevPrompt`, repositório, `PromptService`, controller fino e partials htmx, com seed em `scripts/sql/seed_prompts.sql`.

## Ajustes pós-primeira avaliação (2026-09-23)

Após rodar a primeira avaliação real (10 prompts de classificação, 6 de nome), três ajustes: (1) o botão "Exportar CSV" virou um checkbox "Exportar CSV após avaliar" no formulário de avaliação — o CSV é salvo na mesma requisição do Avaliar, refletindo exatamente os resultados exibidos (sem re-executar o Jev), e a confirmação do caminho aparece no próprio resultado; (2) a extração de nome agora remove pontuação (vírgula, ponto-e-vírgula, dois-pontos, aspas, parênteses, !, ?, hífen) das bordas dos segmentos incluídos — corrige nomes como "João da Silva," — preservando pontos finais ("Jr."); (3) o exemplo "Me lembra de pagar a conta de luz amanhã" foi reclassificado de `finance:add` para `notes:add` (lembrete não é dado financeiro sendo adicionado).
