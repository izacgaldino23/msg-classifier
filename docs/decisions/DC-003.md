# Get contact info

Agora vamos para a parte de buscar dados de contato. Já temos o fluxo de adicionar, então agora vamos para o fluxo de buscar. O usuário vai sempre solicitar passando alguma informação, ou um nome ou pra ver se já existe um número salvo.

Para caso de fornecer somente um nome, vamos buscar, tentando fazer sempre um clean no termo buscado, assim conseguiremos encontrar mais facilmente. Verficar qual melhor maneira de fazer isso.

Em caso de número sempre dar um clean nele antes de buscar.

## Caso tente salvar um número que ja existe

Devolver mensagem falando que o contato já existe, e também com o nome do usuário. Não vamos falar de update agora.

Isso tanto para telefone quanto para email.

## Melhore o UI

Hoje nosso ui esta muito simples, gosto do css atual pelas cores. Mas para melhorar a usabilidade por enquanto, vamos mudar para o https://picocss.com/docs.

Ainda gostaria de ver o resultado com essas informações e o novo que será acrescentado, mas pode reestruturar. Nada muito complexo, quero o básico que funcione.

## Implementação (2026-09-22)

- **`models.Contact.NameNorm`** — coluna normalizada (minúsculas, sem acentos via NFD, espaços colapsados) para busca por nome; preenchida no `Create` e backfilled no startup para linhas antigas.
- **`models`** — novas ações `ActionContactFound` / `ActionContactNotFound` / `ActionContactDuplicate`; `UseCaseOutcome.SearchTerm` (termo buscado, usado na mensagem de não encontrado).
- **`services.ContactService.Get`** — fluxo `require`: prioridade telefone → email → nome; telefone/email sem chamada Jev; nome via `ExtractName` + `normalizeName` + `LIKE %term%` em `name_norm`; nada extraível → `contact_no_data`.
- **`services.ContactService.Add`** — checagem de duplicado (telefone, depois email) antes da extração de nome; duplicado → `ActionContactDuplicate` + contato existente (sem gastar chamada Jev).
- **`services.normalizeName`** — lowercase + NFD (remove diacríticos) + colapso de espaços.
- **`cmd/api/main.go`** — `BackfillNameNorm()` após o `AutoMigrate`.
- **UI** — migração para Pico.css (tema dark), `result.html` como `<article>` com branches encontrado/não-encontrado/duplicado; trace de segmentos no `<footer>`.
