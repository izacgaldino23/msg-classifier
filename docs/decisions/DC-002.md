# Extração de informações de contato

Por enquanto não sei como vou extrair informação do contato, mas preciso de algumas opções para quando cair nesse caso de uso. Pelo json decidi que quero ter como dados de contato telefone e email. 

O problema é que não tenho como extrair essas informações e queria usar uma maneira simples e segura. Basicamente o que precisaremos extrair é nome ou referencia do contato e o contato em si. que no caso é telefone ou email. 

Para telefone aqui no brasil temos formatos padrões, temos para celular o ddd + 9 + 8 digitos, e para telefone fixo o mesmo, porem sem o digito 9. Podendo estar formatado ou não.

O email é universal, sem muito mistério.

A dificuldade é encontrar o meio correto de extrair sendo que a mensagem do usuário é digitada. 

## Email ou telefone?

Temos isso aqui também, podemos usar o jev para decidir, podemos usar o Noul ou o Score pra isso. Podemos usar a api do jev como referencia: https://docs.typesafe.ai/primitives.

## Salvar já?

Sim, por agora quero salvar essa info em algum arquivo local que seja fácil de migrar depois, então acho que pode ser sqlite.

Como vamos avançar para essa etapa, acho que podemos usar o Gorm e suas entidades para manter o banco sincado com nossas estruturas.

## Qual abordagem seguir?

Vamos elencar nossas opçoes com pros e contras, para escolher antes de planejar.

## Implementação (2026-09-22)

- **`pkg/jev`** — correções de Noul: `JevAnswerNoul.Noul` `string` → `float64` (a API retorna número); `JevQuestionNoul` com `True`/`False` planos → `criteria: {true, false}` aninhado; o validador mantém a exigência das duas descrições.
- **`internal/services/extraction.go`** — `ContactExtractor`: `ExtractPhone` (regex BR, normaliza para 10/11 dígitos), `ExtractEmail` (primeiro match + span), `ExtractName` (remove spans → segmentos → um `MakeJevRequest` com Noul `segment_0..N` → `NameResult` com nome unido + trace por segmento, `Included` = noul > 0.5); seam `jevRequester` para mock.
- **`internal/models`** — entidade Gorm `Contact` (ID, Name, Phone/Email nullable, timestamps); `SegmentScore` (texto, score, included); `UseCaseOutcome.Contact` + `UseCaseOutcome.Segments`; ação `ActionContactNoData`.
- **`internal/services/contact.go`** — `Add`: extrai telefone/email → nenhum → `ActionContactNoData`; senão extrai nome → persiste via Gorm → `ActionContactAdd` + contato salvo + trace de segmentos.
- **`cmd/api/main.go`** — SQLite via glebarez (pure-Go, zero CGO), `DB_PATH` (default `contacts.db`), `AutoMigrate(Contact)`, injeção do extractor + DB.
- **`internal/config`** — `DB_PATH` no singleton de env.
- **`web/templates/partial/result.html`** — trace do processo: bloco de classificação sempre visível + bloco por ação (contato salvo com ID, campos e trace de extração por segmento; mensagem de sem dados; classificação).
- Falhas: Jev fan-out → `ErrUpstream` → 502; sem telefone/email → 200 no-data; falha de banco → 500 com `%w`.
